These are logical build-output selectors, not claims of published binary availability.
This release names no published release archive.

## Upstream research artifacts

The reference revision includes `scripts/research-artifact.py` and the `Research artifact` workflow.
They build the committed sources on native ARM64 Linux into one versioned archive.
Each build also writes an external build manifest and a `SHA256SUMS` file.
The archive keeps the repository-relative paths in the table above.

The manifest records the version, source commit, kernel release, toolchain, and package versions.
It also records the SHA-256, size, and mode of each payload file.
A build ID hashes the recorded build identity and inputs.
The module requires the recorded kernel release, a compatible configuration, and compatible symbol versions.
The upstream build does not sign the module.

A release build of this revision reports its identity in three places:

- `owlbeard --version` prints the `owlbear.build/v1` identity as JSON.
- `modinfo -F` reports the module's `version`, `source_commit`, and `build_id`.
- The `build` field of the `owlbear.control.v1` reply repeats the daemon identity.

For outputs from this revision, `source_commit` equals the reference revision.
Ordinary development builds report an unrecorded development identity.

The archive payload also contains attack fixtures, preload libraries, separate eBPF objects, and build inputs.
This release declares none of those files.
The upstream checksums detect changed bytes; they do not authenticate a publisher.
